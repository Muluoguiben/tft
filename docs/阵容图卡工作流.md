# 阵容图卡工作流

更新时间：2026-04-28

目标：把每套正式阵容沉淀成一张可临场扫描的图卡，并保证图卡内容来自已验证的阵容卡，而不是由图像模型自由发挥。

## 工作流总览

```text
数据复核
  -> 中文阵容卡
  -> 结构稿
  -> GPT Image2 提示词
  -> GPT Image2 图卡
  -> 人工 QA
  -> 入库引用
```

## 1. 数据复核

先确认阵容是否值得做图卡。

必须记录：

- 适用版本、服务器和平台。
- 数据来源：优先 `tactics.tools`、`datatft.com`、`tftacademy.com`，补充 `MetaTFT`、`LoLCHESS.GG`、`MetaBot`。
- 中文翻译：先核对 `docs/S17中文翻译对照.md`，避免把英文羁绊直译成错误名称。
- 平均排名、前四率、登顶率、登场率和样本量。
- 阵容定位：主力、条件、观察、冷门备选或高风险追分。
- 适玩条件和放弃条件。
- 过渡思路、D 牌节奏、注意事项和转阵出口。

没有数据支撑的阵容可以做观察卡，但不能写成版本答案。

## 2. 中文阵容卡

在 `docs/comps/` 写完整 Markdown 阵容卡。阵容卡必须先于图卡完成。

至少包含：

- 阵容组成。
- 羁绊组成。
- 主 C、主坦、副 C。
- 核心装备和备选装备。
- 棋盘站位。
- 运营节点。
- D 牌节奏：什么时候不搜、什么时候启动、搜到什么质量停手、什么时候上人口。
- 过渡思路：前期用什么打工、装备先合什么、中期如何稳血。
- 注意事项：同行、装备占位、前排质量、图标占位、站位风险等。
- 适玩条件。
- 放弃条件。
- 来源和更新时间。

原则：图像模型只能读取阵容卡，不允许自行补棋子、补装备或补数据。

## 3. 结构稿

结构稿用于锁定信息位置和内容准确性，可以是 SVG、PNG、文本棋盘或阵容模拟器截图。

结构稿必须做到：

- 阵容组成正确。
- 站位方向正确：前排在上，后排在下。
- 装备归属正确。
- 条件和风险写清楚。
- 过渡思路、D 牌节奏和注意事项在图里能直接看见。
- 图内不写来源、网站名、URL 或参考出处；这些放在 Markdown 阵容卡底部。

结构稿不是最终视觉目标，但它是 GPT Image2 图卡的事实基准。

推荐命名：

- `assets/comps/阵容名-版本-structure.svg`
- `assets/comps/阵容名-版本-structure.png`

## 4. GPT Image2 提示词

用 `templates/GPT-Image2-阵容图卡提示词.md` 生成专用提示词，并保存到 `assets/comps/`。

推荐命名：

- `assets/comps/阵容名-版本.gpt-image2-prompt.md`

提示词必须包含：

- 阵容名和版本。
- 阵容定位和强度标记。
- 8 人口和 9 人口组成。
- 核心羁绊。
- 四行棋盘站位。
- 主 C、主坦、副 C 装备。
- 适玩条件。
- 放弃条件和风险。
- 底部运营节点。
- 过渡思路。
- D 牌节奏。
- 注意事项。
- 不允许在图里展示来源、网站名或 URL。

## 5. GPT Image2 图卡

使用 GPT Image2 生成 16:9 横版图卡。

推荐命名：

- `assets/comps/阵容名-版本-gpt-image2.png`

生成要求：

- 暗色电竞 UI。
- 中间是棋盘站位。
- 左侧是羁绊和过渡思路。
- 右侧是装备携带。
- 底部是 D 牌节奏、运营节点和风险。
- 中文文字必须尽量清晰。
- 图里不放来源信息，避免挤占临场决策内容。

## 6. 人工 QA

GPT Image2 图卡不能直接入库当成最终结论，必须人工核对。

核对清单：

- 棋子是否和阵容卡一致。
- 8 人口和 9 人口补强是否正确。
- 站位方向是否正确。
- 主 C、主坦、副 C 是否正确。
- 装备是否放在正确棋子身上。
- 羁绊档位是否正确。
- 中文羁绊名是否符合 `docs/S17中文翻译对照.md`。
- 适玩条件和放弃条件是否没有变形。
- 过渡思路是否明确，不只是空泛描述。
- D 牌节奏是否明确到阶段和人口。
- 注意事项是否覆盖最容易输的点。
- 图里是否误写来源、网站名、URL 或参考出处。
- 图中是否出现不存在的数据、胜率或额外棋子。
- 中文是否可读，是否有明显错字或乱码。
- 手机和电脑上是否能看清核心信息。

如果图卡有小的视觉误差但不影响使用，可以标注“GPT Image2 版，以 Markdown 为准”。如果棋子、装备或站位错了，必须重新生成。

## 7. 入库引用

通过 QA 后，在对应阵容卡顶部引用 GPT Image2 图卡。

示例：

```md
![木灵小法师 GPT Image2 阵容图卡](../../assets/comps/木灵小法师-17.1b-gpt-image2.png)
```

图片下方必须保留摘要：

```md
图卡摘要：小法师后排主 C，拉莫斯或波比主坦。没有小法三星路径时不要硬玩。
```

如果 GPT Image2 图卡仍有轻微文字误差，必须写：

```md
注：图卡用于临场扫描；如图中文字与下方 Markdown 冲突，以 Markdown 为准。
```

## 8. 校验

每次新增或替换图卡后执行：

```sh
file assets/comps/阵容名-版本-gpt-image2.png
git diff --check
git status --short
```

如果修改了 CSV，再确认 CSV 可解析。
