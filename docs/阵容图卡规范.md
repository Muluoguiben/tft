# 阵容图卡规范

更新时间：2026-04-30

目标：每套正式比赛阵容最终都应有一张可临场扫描的阵容图卡。图卡必须把阵容组成、棋盘站位、羁绊、关键棋子携带装备、过渡思路、D 牌节奏和注意事项放在同一张图里，减少比赛前反复读长文字的成本。

## 最终生成方式

最终成品图卡优先使用 `GPT Image2` 生成。图像模型只负责视觉呈现，不负责策略判断。

标准流程：

1. 先在 `docs/comps/` 写清楚阵容组成、站位、装备、羁绊、适玩条件和放弃条件。
2. 再用 `templates/GPT-Image2-阵容图卡提示词.md` 生成图像提示词。
3. 使用 `GPT Image2` 生成一张 16:9 阵容总览图。
4. 人工核对棋子、装备、站位、羁绊和中文文字是否和 Markdown 一致。
5. 通过后保存到 `assets/comps/`，并在对应阵容文档顶部引用。

完整执行流程见 `docs/阵容图卡工作流.md`。

SVG、文本棋盘或手绘图可以作为结构稿，但不作为最终视觉目标。最终图卡必须接近阵容模拟器或 TFTFlow 这种“一眼看懂阵容”的效果。

## 使用场景

- 赛前快速复习阵容池。
- 对局中确认站位、主 C、主坦和装备优先级。
- 复盘时对照实际成型质量和理想成型质量。

## 图卡必须包含

- 阵容名：例如 `木灵小法师`、`牧羊维克托`。
- 适用版本：例如 `TFT Set 17 / 金铲铲 S17 / 17.1b`。
- 阵容定位：例如运营、赌阵、快 9、转职限定、高上限、保分。
- 最终人口：8 人口和 9 人口分别要上哪些棋子。
- 羁绊列表：只展示关键羁绊和达成档位，不堆无关小羁绊。
- 棋盘站位：纯前排、主坦和召唤前排默认第一排；常规后排默认最后一排；第二排/第三排只用于拉扯、防切、控制或特殊机制。
- 棋子星级：必须在阵容组成和棋盘站位里标明核心质量；默认 1-4 费二星、5 费一星，赌阵/追三星阵容和五费主 C 二星必须单独写清。
- 装备携带：主 C、主坦、副 C 的装备直接显示在棋子旁边或下方。
- 备选装备：可以放在侧边栏，不要挤占主棋盘。
- 关键条件：例如必须有转职、特定强化、特定星神、开局胡牌或低同行。
- 推荐星神：S17 阵容必须展示星神优先级和止损星神；如果某个星神不适合，也要在阵容卡文字里写清楚原因。
- 推荐海克斯：至少展示 3-4 个关键强化方向，区分经济、装备、战力、D 牌或专属条件，不只写“拿战力强化”。
- 纹章/转职：至少展示 2-3 个可用纹章、推荐携带者和开出的羁绊上限；转职限定阵容必须写清楚“无转职降级或不玩”。
- 风险提示：例如同行多不能硬玩、低血不能贪 9、无转职降级。
- 过渡思路：前期用什么打工、装备先合什么、中期目标是什么。
- D 牌节奏：明确什么时候不搜、什么时候启动、搜到什么质量停手、什么时候上 9。
- 注意事项：至少写 3 条最容易犯错的点，例如同行、装备占位、前排质量、转阵条件。
- 可转方向：图卡里至少保留一个失败时的转阵出口。

图卡里不要写来源、网站名、URL 或参考出处。来源记录放在 Markdown 阵容卡和数据表里；图卡只保留对局中能直接执行的信息。

## 推荐版式

```text
标题区 | 阵容名 / 版本 / 定位 / 强度等级

左侧栏 | 羁绊列表 / 过渡思路 / 适玩条件

中心区 | 4 行棋盘站位
前排 | 主坦 + 纯前排 + 召唤前排 + 吃伤害棋子
第二 | 半坦 / 战士 / 拉扯位 / 防切位
第三 | 保护位 / 功能位 / 控制位 / 特殊机制位
后排 | 主 C + 副 C + 工具人

右侧栏 | 主 C 装备 / 主坦装备 / 副 C 装备 / 推荐星神 / 注意事项

底部区 | D 牌节奏 / 推荐海克斯 / 纹章转职 / 关键提醒 / 可转方向
```

## 视觉风格

当前推荐使用“暗色电竞一图流”风格，而不是纯表格或极简卡片：

- 深蓝黑或墨绿色背景，搭配金色、青绿色和阵容主题色边框。
- 顶部放阵容徽章、阵容名、版本、定位、强度标记和一句话总结。
- 中间必须有阵容组成横排和棋盘站位，棋盘格优先使用六边形或接近游戏棋盘的形状。
- 左侧用图标 + 数字档位展示核心羁绊，再展示适玩条件。
- 右侧展示核心装备和推荐星神，文字要短，避免小字堆叠。
- 底部用流程节点展示运营节奏，节点之间用箭头连接；海克斯和纹章模块必须放在图内可见区域。
- 风险模块使用红色或警示色，和适玩条件区分开。

## 站位方向

站位必须符合人类阅读顺序：从上到下是前排到后排。

```text
前排 | 坦克  .    .    主坦  .    .    坦克
第二 | .     控制 .    .     .    控制 .
第三 | .     .    功能 .     .    .    .
后排 | .     .    主C  .     .    副C  .
```

不要把后排放在第一行、前排放在最后一行。

## Markdown 引用方式

阵容图卡放在 `assets/comps/`，阵容文档放在 `docs/comps/`。引用示例：

```md
![木灵小法师阵容图卡](../../assets/comps/full/woodland-veigar-17.1b.avif)
```

正式阵容卡优先引用 `assets/comps/full/*.avif`。JPG 文件只作为网页 `<picture>` 兜底和极旧环境兼容，不作为 Markdown 首选链接。

图片下方必须保留文字摘要，例如：

```md
图卡摘要：小法师后排主 C，拉莫斯主坦单顶，库奇副 C。没有小法三星路径时不要硬玩。
```

## 制作优先级

1. 先给最终比赛阵容池里的主练阵容制作图卡。
2. 再给条件阵容和冷门备选制作图卡。
3. 观察阵容可以先用文本棋盘，等确认进入正式阵容池后再补图。

## 质量要求

- 结构稿可以使用 PNG/SVG，但正式站点资源必须导出为预览 AVIF 和高清 AVIF；高清查看图宽度建议保持 `3000px` 以上，允许按信息密度增加高度，避免为了固定 16:9 导致文字过小。
- 图卡必须能在手机和电脑上直接看清棋子、星级、装备和站位。
- 棋子卡必须同时能看出费用和星级，不能只保留费用数字。
- 装备图标旁边最好保留中文名，避免只靠图标造成误读。
- S17 图卡里的星神模块必须来自 `docs/S17星神4-7恩赐与阵容适配.md` 和对应阵容卡，不能让图像模型自由发挥。
- 使用 `GPT Image2` 生成时，不能要求模型自行补充未知棋子、未知装备或未知数据；所有内容必须来自阵容卡。
- 如果图片来自外部工具截图，需要记录来源和截图日期。
- 如果图卡内容和 Markdown 文字冲突，以最新数据复核后的结论为准，并同步更新两处。
- 不要把图卡做成纯装饰图；它必须能指导实际对局操作。
- 图卡信息密度不能低于基础一图流：只有阵容、羁绊、站位和装备是不够的，必须额外包含棋子星级、过渡、D 牌节奏、推荐海克斯、纹章/转职和注意事项。
