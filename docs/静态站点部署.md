# 静态站点部署

更新时间：2026-04-30

本项目已经接入 React + Vite。页面用 React 负责应用入口和导航壳，现有阵容渲染逻辑作为模块加载；构建后输出纯静态文件，仍然可以部署到 GitHub Pages。

## 本地查看

首次运行先安装依赖：

```sh
npm install
```

开发预览：

```sh
npm run dev
```

然后访问：

```text
http://127.0.0.1:5173/
```

生产构建：

```sh
npm run build
```

## 文件结构

- `index.html`：Vite 入口，挂载 React 应用。
- `src/main.jsx`：React 应用壳，负责顶部导航和加载阵容渲染模块。
- `vite.config.js`：Vite 构建配置，使用相对路径以兼容 GitHub Pages 子路径。
- `package.json`：本地开发、构建和预览脚本。
- `site.css`：页面样式，负责暗色电竞 UI、棋盘、卡片和响应式布局。
- `src/data/`：阵容索引、快照、棋子、装备、羁绊和详情数据。
- `site.js`：梯度首页、筛选路由和旧版详情渲染逻辑；后续可以继续拆成 React 组件。
- `scripts/copy-vite-static.mjs`：构建后只复制页面需要的 AVIF、必要 JPG 兜底和 Markdown 文档，避免把 raw PNG/JPG 源素材发布到线上。
- `.github/workflows/pages.yml`：GitHub Pages Actions 构建和部署流程。
- `_config.yml`：旧版分支部署时的 GitHub Pages 排除规则；Actions 部署主要依赖 `scripts/copy-vite-static.mjs` 控制产物。
- `assets/s17/`：本地棋子、羁绊、装备、星神图片。
- `assets/comps/preview/`：网页内加载的轻量一图流预览图，站点优先使用 AVIF，JPG 作为兜底。
- `assets/comps/full/`：点击查看的高清一图流，站点优先使用 AVIF，JPG 作为兜底。

## 页面结构

- `#/`：阵容梯度首页，按 OP、T1、T2 分组展示多套阵容。
- `#/snapshot/2026-04-30-17.2-day2`：查看指定日期和版本快照。
- `#/snapshot/watch`：只看待复核阵容。
- `#/snapshot/all`：查看当前和历史归档。
- `#/tier/OP`：只看 OP 阵容。
- `#/tier/T1`：只看 T1 阵容。
- `#/tier/T2`：只看 T2 阵容。
- `#/react/comp/woodland-veigar`：木灵小法师详情页，包含羁绊、站位、装备、星神、运营节奏和转阵出口。

首页不能只放单套阵容。新增阵容时，应先进入梯度首页，点击阵容卡后再进入详情页。

## GitHub Pages

推荐使用 GitHub Actions 部署。仓库已经提供 `.github/workflows/pages.yml`：

- 推送到 `main` 或 `master` 后自动执行 `npm ci`。
- 执行 `npm run build`，生成 `dist/`。
- 上传并部署 `dist/` 到 GitHub Pages。

仓库设置里需要把 Pages Source 设为 `GitHub Actions`。

## Cloudflare Pages

如果用 Cloudflare Pages：

- Build command：`npm run build`
- Build output directory：`dist`
- Root directory：仓库根目录

## 后续扩展

新增阵容时，优先把阵容数据沉淀到 Markdown 阵容卡，再同步到 `src/data/comps-index.js` 和 `src/data/comps/<id>.js`。同时必须绑定时间快照字段，例如 `snapshotId`、`patch`、`reviewedAt`、`sourceUpdatedAt`、`status`、`previousTier`。不要只做图片版一图流；网页里必须展示：

- 阵容组成
- 棋盘站位
- 核心羁绊
- 主 C / 主坦 / 副 C 装备
- 推荐星神
- 适玩条件
- 放弃条件
- 运营节奏
- 转阵出口

新增或替换一图流后，需要同步生成 AVIF：

```sh
node scripts/convert-comps-to-avif.mjs
```

Markdown 阵容卡顶部优先引用 `assets/comps/full/*.avif`；如果需要兼容极旧浏览器，JPG 只保留给网页 `<picture>` 兜底，不作为首选文档链接。
